4. URMA 批量分析

本章始终使用全量 TopN，不受总览五段筛选影响。
三级口径：Client Get → 逻辑 URMA Write → WR分片。每条 URMA_ELAPSED_TOTAL 对应一个 WR chunk。当前读取实现顺序异步 post 两个 WR、随后统一 reap；同一逻辑 Write 的关键耗时取两个 URMA Elapsed Time 的最大值，不求和，两个 WR 均在明细中展示。Inflight WR 是发送端 URMA manager 的全局在途快照，不是该 Get 的 WR 数。

Data Worker 粒度分析

范围：本章始终使用全量 TopN，不受总览五段筛选影响。逐 Trace 位置口径：DS_KV_CLIENT_GET transportType 是本次 Client→Worker 实际传输：SHM=本节点共享内存；UB=远端 Data Worker；TCP=位置不确定（可能是远端，也可能是同节点 SHM 失败回退）；缺字段标“未确认”。该结论仅覆盖当前 TopN 输入，不外推整个运行。DS_POSIX_GET 仅用于标识有日志证据的处理 Worker，不能替代访问位置。异常耗时统一按 ≥5ms、≥20ms 高亮。
